# Fixture extraction boundary

This is Task #56 Stage 2 provenance, not a new execution implementation or a
qualified runtime claim. [fixture-ownership.json](fixture-ownership.json) records
52 reviewed source inputs by Pear checkpoint, relative path and content digest,
with proposed single-owner destinations and the assertions each binding must
retain. The contracts/shared-Abort package is already recorded separately in
[source-import.json](source-import.json); its README status and tests are unchanged.

Of these future inputs, 25 match a committed blob, 26 are absent from the named
checkpoint tree and one differs from its committed blob. The latter inputs are
content-pinned retained owner sources; their checkpoint commits alone do not
recover them. They must become an admitted immutable source package or exact
import before execution. Original source authority and retention remain in place
until accepted cutover. The map is a dependency review, not a 52-file copy list.

The existing FixtureContext already bypasses owned-game preparation and supplies
the execution interval. Preserve direct_v1's original execution and assessment,
APISession/APIObserver, all original failures, cleanup and seven fixture oracles.
The required changes are narrowly bounded:

1. Bind a fresh owned output root, its storage volume and current operation
   interval; preserve alias and ownership refusal checks.
2. Bind exact synthetic seed preimages and rebuilt ntdll/FEX digests. Preserve
   source-byte checks and the complete prefix inventory comparison.
3. Bind the canonical candidate view, exact runtime receipt, helper roots and
   policy inputs. Preserve bundle/dependency architecture closure and actual
   current signature/profile/authority checks before and after execution.
4. Keep private/historical phase selection on the Pear game path. Fixtures use
   identified generic configuration; real-game routing still requires owned
   inputs. A candidate label never grants admission of new artifact bytes.
5. Replace whole tools/host discovery with a complete pinned producer manifest,
   including dynamic sources. Preserve snapshots and operation-end rechecks;
   raw sources containing personal paths stay local.
6. Move the one exact context/description type with both consumers. Defer unused
   branch imports mechanically; preserve original execution, errors, native
   coverage, cleanup and graphics assertions. Do not introduce another launcher.

Dynamic reuse adds four Task7 captured source files and nine Wine helper modules,
plus three separately captured signing/host-policy files. Their exact identities
and repository-relative paths are in the JSON map. Existing capture mechanisms
verify original bytes and avoid old CLI entrypoints. A default old REPO or
graphics_repo lookup is not an acceptable fallback for the new package.

Runtime owns cross-component fixture admission and oracles. Pear retains game,
account, Preview and manager policy. Component-local tests remain with their
component; a pinned package is consumed instead of creating a second editable
copy. Four diagnostic readers have already moved to FEX; the JSON identifies
them. Other mixed parser/candidate-policy files remain unresolved source splits,
and are not claimed to have moved. Host authorization source is an explicit input,
not authority inherited from a prior receipt.

The next gates are source-preserving adaptation and its original negative tests,
then the actual seven host fixture runs on the rebuilt candidate. The current
portable contract/shared-schema tests do not substitute for those results.
No local fixture path, private payload identity or signing material is recorded
here. No Stage 3 builder or Stage 4 runner implementation is added by this record.
