## Verification Results

On the existing Apple Silicon/macOS development host, with the pinned ARM64 Python
invocation and artifact-specific profile, run each request with:

```sh
python3 -B -m pear_runtime.fixtures inspect --request "$FIXTURE_REQUEST"
/usr/bin/arch -arm64 "$ARM64_PYTHON" -B -m pear_runtime.fixtures execute --request "$FIXTURE_REQUEST"
python3 -B -m pear_runtime.fixtures.release --request "$RELEASE_REQUEST" --output "$FRESH_RELEASE_RECORD"
```

- All seven fresh operations passed: TLS/thread, SEH/unwind, suspend/context,
  code invalidation, guest fault guard, configured memory and original rendering.
  Each observed guest exit 42, current authority before/after, complete owned
  cleanup, unrelated sentinel survival and unchanged final source/input identities.
- Actual observed required native processes/images were ARM64 and untranslated.
  The finite observation boundary does not establish complete late-load coverage,
  gameplay, Steamworks, or ordinary-user qualification.
- Rendering retained the original backend, scalar repair, Metal validation,
  pipeline and readback assertions. It does not replace pairing or visible-frame
  controls, which remain pending.
- 281 portable tests passed, with zero failures, errors or skips. This includes
  original pure oracles, admission/refusal, timeout/final-receipt and release cases.
- Independent release passed for all seven successes and the initial failed run:
  74 recorded process identities, 32 group IDs, two observations, no owned output
  handles and the existing coordination lock available. No runtime process was
  signaled by that checker. PID reuse and unavailable observations are explicit.
- The initial TLS execution's runtime assessment passed, but its whole operation
  failed because the old strict decoder rejected new authority timing fractions.
  The new control record uses its own bounded duplicate-key-rejecting reader;
  original case/event decoders remain unchanged. Four refusal/regression tests
  passed, and a fresh TLS run passed with a new immutable producer manifest.
- Diff hygiene has one reviewed formatting exception: the exact executed

  retained unchanged; all other whitespace checks pass. The warning is not
  reported as a clean unrestricted `git diff --check`.

  rechecked unchanged. Original Preview/runtime/private state was not modified.
- The 17 exact historical provider files have 34 existing inline-notice warnings.
  Their original attribution/terms and adjacent NOTICE were manually reviewed;
  this is not an automated source-notice pass. Other checkpoint source notices
  are explicit. Exact historical bytes were not silently rewritten.

Historical source/build equality and native Windows references retain only their
